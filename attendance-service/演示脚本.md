## 一、正式演示（9 步，时间轴可直接照着念）

### 第 1 步（0:00–0:40）多角色登录

```bash
curl -s -X POST http://localhost:8081/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"student1","password":"<演示口令>"}'
```

对 `deptA`、`center` 各发一次。

**预期**：都返回 `"code":200`，`data` 里 `roleId` 分别是 1 / 2 / 3，`token` 各不相同。

**讲解词**：
> "系统里四类角色，登录统一由权限服务发 Token，返回的 roleId 决定后续能看到什么数据。
> 三个服务的鉴权都调这一个接口，Token 逻辑只维护一份。"

> **一次性取齐后续要用的 4 个 token**（在同一个终端里执行，变量后面直接用）：
> ```bash
> LOGIN() { curl -s -X POST http://localhost:8081/api/auth/login -H "Content-Type: application/json" \
>   -d "{\"username\":\"$1\",\"password\":\"<演示口令>\"}" | grep -o '"token":"[^"]*"' | cut -d'"' -f4; }
> T1=$(LOGIN student1)   # 学生（已录用岗位1）
> T2=$(LOGIN student2)   # 学生（未录用）
> TD=$(LOGIN deptA)      # 部门管理员
> TC=$(LOGIN center)     # 助学中心管理员
> echo "${#T1} ${#T2} ${#TD} ${#TC}"   # 四个数字都大于 0 说明都拿到了
> ```
> `<演示口令>` 替换成仓库 README 里给出的演示口令（5 个账号同一口令）。

### 第 2 步（0:40–1:00）初始状态：工时为零

```bash
curl -s "http://localhost:8083/api/attendance/mySubsidy?month=2026-11" -H "token: $T1"
```

**预期**：`recordCount: 0`，`totalHours: 0.0`，`totalAmount: 0.00`。

**讲解词**：
> "先看基线，这个学生本月还没有工时，补贴是 0。"

### 第 3 步（1:00–1:50）核心亮点：未录用学生签到被拦

先拿 student2 的 token（`$T2`），然后：

```bash
curl -s -X POST http://localhost:8083/api/attendance/checkIn -H "Content-Type: application/json" \
  -H "token: $T2" -d '{"jobId":1}'
```

**预期**：`{"code":400,"msg":"您未被该岗位录用，无法签到"}`

**讲解词**（本场最重要的一段）：
> "注意这是**跨服务校验**：工时服务自己并不保存录用关系，它拿着 Token 里的 userId 去问岗位服务
> 「这个人被岗位 1 录用了吗」，拿到 false 才拒绝。
> 同时前面已经过了一道关——Token 是问权限服务校验的。
> 所以一次签到要跨两个服务验证，任何一环不通过都不放行。"

### 第 4 步（1:50–2:20）student1 正常签到

```bash
curl -s -X POST http://localhost:8083/api/attendance/checkIn -H "Content-Type: application/json" \
  -H "token: $T1" -d '{"jobId":1}'
```

**预期**：`code:200`，`data` 里 `jobName:"图书馆图书整理助理"`、`hourSalary:25.0`、`deptId:1`。

**讲解词**：
> "签到成功时，把岗位名、时薪、部门一起**快照**进这条记录。
> 为什么不实时查岗位？因为时薪以后会调整，历史工资必须按当时的标准结算——这是工资系统的常识。"

### 第 5 步（2:20–2:45）重复签到被拒

再执行一次第 4 步的命令。

**预期**：`{"code":400,"msg":"您在该岗位已签到且未签退，请先签退"}`

**讲解词**：
> "防止重复打卡。这条在数据库层还有唯一约束兜底：即使两个请求同时到达，也只会有一条能写进去——
> 这是我们测试时真的测出过并发 bug 之后补上的。"

### 第 6 步（2:45–3:30）录用联动：student2 被录用后可以签到了

由 deptA 录用 student2（申请 id=2，是预置的待审核申请）：

```bash
curl -s -X POST http://localhost:8082/api/job/auditApply -H "Content-Type: application/json" \
  -H "token: $TD" -d '{"applyId":2,"applyResult":"accept","remark":"面试通过，录用"}'
```

然后 student2 再签到一次：

```bash
curl -s -X POST http://localhost:8083/api/attendance/checkIn -H "Content-Type: application/json" \
  -H "token: $T2" -d '{"jobId":1}'
```

**预期**：审核返回 200；student2 签到也返回 200。

**讲解词**：
> "同一个人、同一个岗位，刚才被拒绝，现在通过了——变的不是工时服务的代码，
> 而是岗位服务里的录用关系。三个服务各自独立，数据靠接口联动。"

> 注意：岗位 1 需要 2 人、已录 1 人，这次录用后名额招满，岗位状态会变成"已招满"。
> 工时服务只拦"已下架"，招满不影响已录用学生打卡——这正是当初加 `getJob` 接口的原因。

### 第 7 步（3:30–4:40）签退与金额核算

**先说明**：签退要求签到满 1 分钟，否则返回 400「签到时长不足 1 分钟」。
演示到这一步通常已经过了 1 分钟；若没有，就在这一步讲设计，等满 1 分钟再执行。

```bash
curl -s -X POST http://localhost:8083/api/attendance/checkOut -H "Content-Type: application/json" \
  -H "token: $T1" -d '{"jobId":1}'

curl -s "http://localhost:8083/api/attendance/mySubsidy?month=2026-11" -H "token: $T1"
```

**预期**：签退返回 `workMinutes`、`workHours`、`amount`；
查补贴返回的 `totalAmount` 与签退的 `amount` **完全一致**。

金额校验口径：`25 元/小时 × 分钟数 ÷ 60`，保留 2 位小数。
例如 3 分钟 = 1.25 元。可以当场用手机算一下对给老师看。

**讲解词**：
> "金额用 BigDecimal 按**精确分钟**算，不是先四舍五入到小时再乘时薪——否则零头会累积偏差。
> 明细和汇总用的是同一套算法，所以对得上。"

### 第 8 步（4:40–6:00）数据隔离与越权拦截

```bash
# 部门管理员查本部门：200
curl -s "http://localhost:8083/api/attendance/deptSummary?month=2026-11" -H "token: $TD"

# 部门管理员查别的部门：403
curl -s "http://localhost:8083/api/attendance/deptSummary?month=2026-11&deptId=2" -H "token: $TD"

# 部门管理员查全校：403
curl -s "http://localhost:8083/api/attendance/schoolSummary?month=2026-11" -H "token: $TD"

# 中心管理员查全校：200
curl -s "http://localhost:8083/api/attendance/schoolSummary?month=2026-11" -H "token: $TC"
```

**预期**：200 → 403 → 403 → 200。

**讲解词**：
> "部门管理员的 deptId 不是前端传的，是从权限服务按 Token 查出来的，
> 所以他改参数也绕不过去。三个角色三种视野，这是数据权限的落地。"

### 第 9 步（6:00–7:00）月度结算与发放（闭环）

```bash
# 1) 中心管理员结算本月：把已签退工时固化成发放单
curl -s -X POST http://localhost:8083/api/attendance/settle -H "Content-Type: application/json" \
  -H "token: $TC" -d '{"month":"2026-11"}'

# 2) 再结算一次，演示幂等（不会多出一张单）
curl -s -X POST http://localhost:8083/api/attendance/settle -H "Content-Type: application/json" \
  -H "token: $TC" -d '{"month":"2026-11"}'

# 3) 查看待发放的发放单（部门管理员只看本部门）
curl -s "http://localhost:8083/api/attendance/subsidyList?month=2026-11&status=0" -H "token: $TD"

# 4) 批量发放
curl -s -X POST http://localhost:8083/api/attendance/pay -H "Content-Type: application/json" \
  -H "token: $TC" -d '{"month":"2026-11"}'

# 5) 学生端看到"已发放"
curl -s "http://localhost:8083/api/attendance/mySubsidy?month=2026-11" -H "token: $T1"
```

**预期**：
1. 首次结算 `createdCount ≥ 1`，`totalAmount` 与第 7 步的补贴金额一致；
2. 第二次 `createdCount = 0`、`refreshedCount ≥ 1`，金额不变（只刷新不新增）；
3. 发放单状态 `待发放`；
4. 发放返回 `paidCount ≥ 1`，`paidAmount` 与结算金额一致；
5. 学生端 `settleStatus: 1`、`settleStatusName: "已发放"`。

**讲解词**：
> "前面看到的补贴是**实时算**出来的，学生随时能查，但那是账面上的数。
> 真正发钱要先**结算**：把工时、金额、包含哪几条打卡记录固化成一张发放单，存进 `t_subsidy` 表。
> 结算之后才打款；打款后再有人补录工时，已发放的金额**冻结不变**——不然已经发出去的钱就对不上账了。
> 重复点结算只会刷新待发放的单，不会多出一张；重复点发放第二次会返回 400，不会重复计数。"

## 二、现场应急（出问题先看这里）

| 现象 | 原因 | 处理 |
|---|---|---|
| 签到返回 400「已签到且未签退」 | 没清 `attendance-service/data` | 停 8083 → 删 data → 重启，重跑 |
| 结算返回 400「该月没有可结算的工时」 | 第 7 步还没签退，或月份写错 | 先完成签退；`month` 必须是 `yyyy-MM` |
| 重复发放返回 400 | 已经发过了（幂等的正常表现） | 直接讲"不会重复发钱"，继续 |
| 登录返回 400「账号或密码错误」 | 口令填错（不是文档里的那个） | 以仓库 README 为准；仍失败就用 `admin` 试 |
| 任何接口 500「XX 服务暂不可用」 | 依赖的服务没起或端口不通 | `netstat` 查 8081/8082，缺哪个起哪个 |
| 签退返回 400「签到时长不足 1 分钟」 | 签到后不到 60 秒 | 等一下再签，或换讲设计要点 |
| 启动报 `ClassNotFoundException` | 用了 `mvn spring-boot:run` | 改用 `mvn -DskipTests package` + `java -jar` |
| 数据看着"花"了 | 多轮演示累积了记录 | 删 data 重来，别现场修数据 |

## 四、答辩可能被追问的问题（背下来）

| 问题 | 回答要点 |
|---|---|
| 为什么工时服务要调两个服务？ | 身份归权限服务、录用关系归岗位服务，工时服务不复制别人的业务数据，符合独立数据库设计 |
| 依赖服务挂了怎么办？ | 写操作直接 500 拒绝（宁可不打卡也不放错人），查询类接口照常可用——已实测 |
| 时薪改了历史工资会不会变？ | 不会，签到时快照，结算用快照值 |
| 并发签到会不会重复算钱？ | 数据库唯一约束兜底（`uk_att_active`），已用并发用例验证只成功一条 |
| 金额为什么不用 double？ | 浮点误差会让明细加总与汇总对不上，统一用 BigDecimal + 精确分钟 |
| 部门和全校汇总怎么做的？ | 汇总只查本服务的记录表（部门、时薪已快照），不需要跨服务 join |
| 实时补贴和"结算"有什么区别？ | 实时补贴是查询视图，随工时变；结算是把金额固化成发放单，打款后冻结 |
| 重复结算/重复发放会不会重复发钱？ | 不会：发放单唯一键 `(user, dept, month)` 拦住重复建单；发放用 `WHERE status=0` 条件更新，第二次影响 0 行 |
| 一个人在两个部门打工怎么算？ | 按部门各生成一张发放单，部门汇总 = 该部门发放单合计，对账不串部门 |
| 超过 12 小时的异常工时怎么处理？ | 签退时自动标 status=2、不计薪；部门管理员（本部门）或中心管理员调 `/confirmAbnormal` 核实：通过 → 计薪，不通过 → 作废留痕；系统记录核实人（`confirm_operator_id`）与核实时间，已核实的记录不允许改结论 |
| 一个学生一个月打卡记录很多怎么办？ | `myRecord` 支持 `page/size`（默认 1/20，上限 100），合计始终按整月算，翻页不会让金额变小 |
| 金额为什么会差 1 分（如 125.01 与 125.00）？ | 每条记录先四舍五入到分再累加，取整位置不同；系统以"明细加总 = 汇总"为准，保证明细、汇总、发放单三者一致 |
